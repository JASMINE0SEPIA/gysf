# Vanilla-style rain restoration

Development branch: `jasmine/weather-vanilla-rain`, based on gysf 0.7.4
(`5c649a8`). The first 0.7.5 development package keeps vanilla rain/snow textures,
column placement, animation and heightmap clipping.

## Changes

- Weather used to fall through to the entity alpha cutoff despite comments
  describing stochastic transparency. Weather now explicitly selects fractional
  coverage. The CPU only removes column alpha below the eight-bit vertex-colour
  range, rather than imposing a second 0.1 cutoff.
- Per-column vanilla sky/block light is retained in the weather primitive's aux1
  lane. The entity-only armour-glint interpretation of that lane is unchanged.
  Weather carries the two light levels through the otherwise unused particle F0
  lanes, then shades with vanilla-style light falloff and the current RT sky
  ambient. This follows day/night, storm attenuation and nearby block lights;
  it replaces the arbitrary 0.12-to-1.9 day/night brightness multiplier.
- Rain intensity follows vanilla continuously from zero to one. The previous
  35% floor and reshaped onset/clearing curve are removed.

These are small independent commits so transparency, lighting and intensity can
be assessed or reverted separately. No new weather settings are added. World
storage, vooxxy and the external LOD API are unchanged.

## Validation

`WeatherCapture` is a development-only replay selected with
`-Dgysf.smoke.weather=true`. It requires a physical copy under
`saves/gysf-weather` in an isolated smoke run directory. It builds a small neutral
courtyard, wall, roof and lamp fixture in that copy. Never point the smoke run
directory at the live PCL profile.

The seven locked-camera captures cover clear daylight, full rain, quarter rain,
unlit night, nearby block lights at night, the view from under a roof, and rain
stopping. Both the old renderer and the candidate complete the same sequence,
including a 0-to-1-to-0 rain transition and 441 extracted columns during full rain.
The candidate produces visibly less obstructive rain, a lighter quarter-density
setting, block-light response and a clear sheltered region. The final clear
capture has no rain columns. This is a short stationary comparison, not visual
acceptance for every biome, resource pack, camera movement or snowfall case.

All 245 Java tests pass, including packed weather light versus glint ownership
and direct tests of the production intensity function. `Test-WeatherTransport.ps1`
executes production Slang coverage/lighting functions in 323 cases: low alpha
must preserve the expected background share, zero alpha must never block, and
light must respond monotonically to illumination without a self-lit dark value.
All runtime shaders compile and pass SPIR-V validation. The log checker has 30
positive/negative cases, including incomplete weather captures and validation
errors. The candidate passes `Assert-VulkanSmokeLog.ps1 -RequireWeather
-RequireNgxClearSync`, exercising DLSS-RR and NGX synchronization without Vulkan
validation reports; native RT LOD allocations return to zero at shutdown.

Evidence is retained locally under `artifacts/2026-10-19/weather/`, including
paired screenshots, state JSON, logs and protected-profile hashes. All 159
recorded live configuration/save/cache/mod files retain their pre-test hashes.
The experimental package is built separately from the installed 0.7.4 mod.

## Remaining rendering boundary

This first pass still uses stochastic weather in the primary ray path. It does
not yet introduce a separate alpha-blended weather layer or DLSS-RR transparency
guides. Grain, fine rain disappearing into temporal reconstruction, and texture
motion stability remain reasons to evaluate that next step against this corrected
baseline. Weather block light is a vanilla-style warm lightmap response, not
per-emitter coloured ray-traced scattering. No per-drop refraction is simulated.
